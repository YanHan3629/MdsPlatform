# 多模态数据空间项目手册

## 1. 项目背景

### 1.1 背景
本项目面向“图文多模态数据”管理与检索场景，目标是打通从数据组织、版本化管理、文件上传、元数据导入、索引构建到在线检索的完整闭环。

在传统数据平台中，图片与文本常分散管理，缺乏统一的版本、索引和可追溯链路；本项目将这些能力统一到一个可扩展的后端体系中。

### 1.2 目标
- 建立多模态数据空间（Space）与数据集（Dataset）管理能力。
- 支持数据版本（Version）与版本内文件全生命周期管理。
- 支持基于 `captions*.json` 自动导入资产与文本标注。
- 支持离线索引构建（Index Builder）与状态回调。
- 支持在线检索（文搜图 / 图搜文）与检索结果增强。

### 1.3 非目标（当前版本）
- 不提供端到端训练平台能力。
- 不覆盖复杂主动学习闭环（如在线增量重建索引策略）。
- 不包含前端实现（仅后端与服务端接口）。

## 2. 项目总体设计

## 2.1 系统组成
项目主要由三部分组成：

1. `services/backend`（Java / Spring Boot）
   - 控制面核心服务
   - 负责空间、数据集、版本、文件、资产、索引、搜索代理

2. `services/search-service`（Python / FastAPI）
   - 在线检索服务
   - 提供内部检索接口：文搜图 / 图搜文

3. `services/index-builder`（Python）
   - 离线索引构建器
   - 读取输入数据并输出 FAISS + Parquet + Manifest

### 2.2 存储与中间件
- PostgreSQL：业务数据与关系建模
- MinIO：对象存储（原始文件与索引文件）
- Redis：缓存/会话等支持能力（由后端依赖）

### 2.3 架构链路（逻辑）
1. 用户通过 Backend 创建 Space / Dataset / Version。
2. 通过文件接口上传图片与 `captions*.json` 到版本仓库。
3. 发布版本后触发索引构建。
4. Backend 调度 Index Builder，构建索引并回调 READY/FAILED。
5. Search Service 通过 Backend 内部 bundle 接口拉取索引并加载。
6. 前端调用 Backend 搜索接口，Backend 代理到 Search Service 并补齐业务字段。

## 3. 领域模型设计

数据库迁移脚本定义于：`services/backend/src/main/resources/db/migration/V4__multimodal_space_schema.sql`。

核心表：
- `mm_space`：多模态空间
- `mm_dataset`：数据集
- `mm_dataset_version`：数据版本
- `mm_asset`：版本资产（图片等）
- `mm_asset_text`：文本标注（caption/title/ocr...）
- `mm_tag` / `mm_asset_tag`：标签体系
- `mm_category` / `mm_asset_category`：分类体系
- `mm_index_version`：索引版本状态与产物路径
- `mm_search_log`：检索日志

设计要点：
- 大多数实体包含 `meta JSONB NOT NULL DEFAULT '{}'::jsonb`。
- 状态字段（status）采用 CHECK 约束，保证状态值合法。
- `mm_dataset_version.active_index_version_id` 指向当前生效索引。

## 4. 核心流程设计

## 4.1 数据上传流程
1. 创建版本：`POST /api/mm/datasets/{datasetId}/versions`
2. 获取预签名上传 URL：`POST /files:begin-upload`
3. 上传文件（图片 + captions JSON）：`PUT /files/content`
4. 发布版本：`POST /publish`

说明：文件管理底层复用了 artifact + MinIO 的已有能力。

## 4.2 索引构建流程
1. 调用：`POST /api/mm/datasets/{datasetId}/versions/{versionId}/build-index`
2. Backend 扫描版本文件并导入 `mm_asset` / `mm_asset_text`。
3. Backend 新建 `mm_index_version` 并启动构建任务。
4. Index Builder 输出：
   - `/indexes/image/faiss.index`
   - `/indexes/image/id_map.parquet`
   - `/indexes/text/faiss.index`
   - `/indexes/text/id_map.parquet`
   - `/indexes/manifest.json`
5. Index Builder 回调 Backend READY/FAILED。
6. Backend 更新 `mm_index_version` 状态并切换 active index。

## 4.3 搜索流程
1. 外部请求进入 Backend：
   - `POST /api/mm/search/text-to-image`
   - `POST /api/mm/search/image-to-text`
2. Backend 根据数据版本解析 active index。
3. Backend 调用 Search Service 内部接口。
4. Search Service 拉取并加载索引 bundle 后执行检索。
5. Backend 结合资产信息返回增强结果（路径、文本、预览链接等）。

## 5. API 设计总览

### 5.1 对外接口
- 空间：
  - `POST /api/mm/spaces`
  - `GET /api/mm/spaces`
  - `GET /api/mm/spaces/{spaceId}`
- 数据集：
  - `POST /api/mm/spaces/{spaceId}/datasets`
  - `GET /api/mm/spaces/{spaceId}/datasets`
  - `GET /api/mm/datasets/{datasetId}`
- 数据版本：
  - `POST /api/mm/datasets/{datasetId}/versions`
  - `GET /api/mm/datasets/{datasetId}/versions`
  - `POST /api/mm/datasets/{datasetId}/versions/{versionId}/publish`
- 文件：
  - `POST /api/mm/datasets/{datasetId}/versions/{versionId}/files:begin-upload`
  - `PUT /api/mm/datasets/{datasetId}/versions/{versionId}/files/content`
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/files`
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/files/content`
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/files/download-url`
  - `DELETE /api/mm/datasets/{datasetId}/versions/{versionId}/files`
- 索引：
  - `POST /api/mm/datasets/{datasetId}/versions/{versionId}/build-index`
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/index-status`
- 资产：
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/assets`
  - `GET /api/mm/datasets/{datasetId}/versions/{versionId}/assets/{assetId}`
  - `POST /api/mm/datasets/{datasetId}/versions/{versionId}/assets/{assetId}/tags`
  - `POST /api/mm/datasets/{datasetId}/versions/{versionId}/assets/{assetId}/categories`
- 搜索：
  - `POST /api/mm/search/text-to-image`
  - `POST /api/mm/search/image-to-text`

### 5.2 内部接口
- Index 回调：
  - `POST /api/mm/internal/datasets/{datasetId}/versions/{versionId}/indexes/{indexVersionId}/ready`
  - `POST /api/mm/internal/datasets/{datasetId}/versions/{versionId}/indexes/{indexVersionId}/failed`
- Bundle 解析：
  - `GET /api/mm/internal/datasets/{datasetId}/versions/{versionId}/indexes/{indexVersionId}/bundle`

## 6. 配置说明

## 6.1 Backend 关键配置
- `MM_SEARCH_BASE_URL`：Search Service 地址（默认 `http://localhost:18080`）
- `MM_PREVIEW_EXPIRE_SECONDS`：预览 URL 过期秒数（默认 `600`）
- `MM_INDEX_BUILDER_IMAGE`：索引构建镜像（默认 `sirius-mm-index-builder:latest`）
- `MM_INDEX_BUILDER_CMD`：索引构建命令（默认 `python /app/build_index.py`）

另需配置 PostgreSQL、MinIO、Redis 相关连接项（见 `application.yml` / `docker-compose.yml`）。

## 6.2 Search Service 关键配置
- `BACKEND_BASE_URL`
- `BACKEND_BEARER_TOKEN`
- `MODEL_PATH`
- `LOCAL_CACHE_DIR`（可选）

## 6.3 Index Builder 关键配置
- `INPUT_DIR`（默认 `/tmp/in`）
- `OUTPUT_DIR`（默认 `/tmp/out`）
- `MODEL_PATH`
- `BACKEND_BASE_URL`
- `BACKEND_BEARER_TOKEN`
- `BACKEND_CALLBACK_READY`
- `BACKEND_CALLBACK_FAILED`
- `OUTPUT_COMMIT_ID`

## 7. 部署与运行手册

## 7.1 前置条件
- Docker / Docker Compose
- 可访问镜像仓库（Docker Hub 或镜像代理）
- 可用的模型目录（例如 `clip_model_chinese`）

## 7.2 启动 Backend 依赖栈
工作目录：`services/backend`

```bash
docker compose up -d --build
```

启动后默认端口：
- Backend: `8888`
- PostgreSQL: `15432`
- MinIO API: `19000`
- MinIO Console: `19001`
- Redis: `6379`

## 7.3 启动 Search Service
工作目录：`services/search-service`

```bash
docker build -t sirius-mm-search-service:latest .
docker run --rm -p 18080:18080 \
  -e BACKEND_BASE_URL=http://<backend-host>:8888 \
  -e BACKEND_BEARER_TOKEN=<token> \
  -e MODEL_PATH=/models/clip_model_chinese \
  -v <local-model-dir>:/models \
  sirius-mm-search-service:latest
```

## 7.4 构建 Index Builder 镜像
工作目录：`services/index-builder`

```bash
docker build -t sirius-mm-index-builder:latest .
```

> Backend 的 `build-index` 会使用该镜像名发起构建任务。

## 8. 端到端使用指南

## 8.1 最短闭环
1. 创建 Space。
2. 在 Space 下创建 Dataset。
3. 创建 Dataset Version。
4. 上传图片与 `captions*.json`。
5. 发布 Version。
6. 调用 `build-index`。
7. 轮询 `index-status`，等待 `READY`。
8. 调用搜索接口进行文搜图、图搜文验证。

## 8.2 数据格式建议
- 图片路径建议稳定且层级清晰（如 `/images/xxx.jpg`）。
- captions JSON 建议采用 COCO 风格结构（包含 `images` 与 `annotations`）。
- `image.file_name` 应可映射到上传文件名。

## 9. 运维与排障

## 9.1 常见问题：Docker 拉取基础镜像失败
现象：`failed to fetch anonymous token` / `connect timeout`。

建议：
1. 检查主机到 `auth.docker.io` 网络连通性。
2. 执行 `docker login` 后重试。
3. 配置 Docker registry mirror。
4. 必要时替换基础镜像源（如 GHCR 镜像）。

## 9.2 常见问题：`meta` 字段 NOT NULL 报错
现象：`null value in column "meta" violates not-null constraint`。

原因：业务插入时传入 `NULL`，而表字段 `meta` 定义为 `NOT NULL`。

建议：
1. 应用层创建对象时给 `meta` 赋默认 `{}`。
2. SQL 插入层做 `COALESCE` 兜底。
3. 确保数据库列默认值为 `'{}'::jsonb`。

## 9.3 索引构建失败排查
- 检查模型目录是否存在且可读。
- 检查输入目录是否包含图片与 captions JSON。
- 检查回调地址与鉴权 token 是否正确。
- 检查 `mm_index_version.error_message` 与构建日志。

## 9.4 搜索服务异常排查
- 确认 Search Service 与 Backend 网络互通。
- 确认 Bundle 内各文件下载 URL 可访问。
- 确认 FAISS/Parquet 文件存在且版本匹配。

## 10. 安全与权限建议

- 内部接口（bundle、回调）应仅在可信网络暴露。
- `BACKEND_BEARER_TOKEN` 应使用最小权限、可轮换密钥。
- MinIO 预签名 key 建议分离读写权限并定期轮换。
- 生产环境请使用 HTTPS、审计日志与访问控制策略。

## 11. 版本演进建议

- 引入异步任务统一编排与任务中心（状态、重试、告警）。
- 增加索引增量更新能力，降低全量重建成本。
- 增加多模型路由能力（按数据集/租户选择模型）。
- 增加检索质量评估与 A/B 实验框架。
