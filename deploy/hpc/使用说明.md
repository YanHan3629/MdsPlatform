# 同济 HPC 按需测试

本部署是原本地系统的独立测试副本，使用 Singularity 和 Slurm。数据、账号密码、对象、模型、回执和追踪记录已迁移；本地 Docker 服务保持原状。HPC 后续产生的数据不会自动同步回本地。

原本地开发对话继续改进功能前，请先读取 [Codex 开发环境交接](./CODEX_HANDOFF.md)，其中说明源码如何更新到远端、验证范围和数据保护要求；本文侧重日常启停操作。

## 启动、连接、停止

在 `E:\VSCodeProject\MdsPlatform` 的 PowerShell 中操作。需要校园网/VPN及已配置的 SSH 公钥。以下 IP 是本次通过 Xshell 实际连接核实并成功使用的地址；如果以后变更，请使用平台域名或重新核实地址，始终保持 SSH 主机密钥校验。

```powershell
# 完整功能：1张L40、7核CPU、48GB内存；就绪后最多30分钟。
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -Minutes 30 -Server 192.168.212.245

# 使用上一条返回的实际作业号，等待 ready=True。
.\deploy\hpc\session.ps1 -Action Status -JobId <作业号> -Server 192.168.212.245

# 保持这个窗口运行，随后打开下面的浏览器地址。
.\deploy\hpc\session.ps1 -Action Connect -JobId <作业号> -Server 192.168.212.245
```

浏览器地址：<http://127.0.0.1:18888/data-space/index.html>。使用原本地平台的账号和密码登录。预签名对象地址经本机 `19000` 端口访问。不要打开本机原来的 `8888` 地址来判断 HPC 部署效果。

测试结束后，在另一个 PowerShell 窗口执行：

```powershell
.\deploy\hpc\session.ps1 -Action Stop -JobId <作业号> -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Status -Server 192.168.212.245
```

Status 无活动作业后，计算资源已释放。停止会话会中断未完成任务，原始数据和已保存结果保留。**仅关闭浏览器或 SSH 隧道不会取消 sbatch 作业，测试结束请执行 Stop。** 即使忘记停止，会话也有就绪时长和 Slurm 总时长双重上限；总时长额外预留15分钟启动、清理时间。排队截止时间为12小时，不是获配资源后的运行时长。

只测数据管理、质量、索引、发布及交付时可选择 `-Mode CPU`：8核、24GB，不启动大模型和问答服务。需要问答时选择 GPU 模式。Start 会阻止同时提交多个本项目作业，避免重复占用资源和打开同一数据库。

默认 `-Server` 为 `logini.tongji.edu.cn`；校园 VPN 与代理分流正常时可以省略该参数。程序不修改 VPN/代理设置，不绕过 SSH 主机密钥校验。计算节点公钥通过已认证的登录连接和自有 Slurm allocation 读取后，才用于建立隧道。

## 限制及文件位置

整个服务栈受 Slurm 分配的 CPU/内存上限控制；动态索引另受步骤级CPU/内存限制。进程上限采用用户 UID 范围的硬限制，可能比 Docker 单容器限制更严格。各常驻服务没有逐项复制 Docker Compose 的独立资源上限。当前适用于本账号按需功能测试，不是多租户生产部署。

仅使用本地已转换、登记的 SIF 镜像。任意新 Docker 镜像不能直接运行，需先在有限 Slurm 作业中转换、验证并登记。

- 程序：`~/apps/mds-platform/`
- 镜像与归档：`~/packages/mds-platform/`
- 迁移备份：`~/backup/mds-platform/snapshot-01/`
- 持久数据库、对象、回执、索引缓存：`~/data/mds-platform/`
- 会话日志：`~/apps/mds-platform/session-<作业号>.log`
- 各服务日志：`~/data/mds-platform/runs/<作业号>/`
- 动态任务日志：`~/data/mds-platform/runtime/<作业号>/<容器ID>/output.log`

不要在登录节点启动应用或构建镜像，不使用 Docker daemon、sudo、长期后台服务。传输时无需申请 GPU。历史日志和任务临时目录为便于审计尚未自动清理；测试结束只释放计算资源，不删除持久数据。存储仍受平台配额和计费规则约束。

## 候选运行器的任务隔离要求

更新运行器时，runtime_cli.py、slurm_exec.py 必须来自同一已核验候选版本；
仅替换 JAR 不会同步更新这两个脚本。切换前停止本轮任务，核对两个脚本的哈希，
同时保留上一版本的脚本组合供回退。不要在任务执行中替换运行器。

任务使用独立 PID、IPC、/root 和 /tmp 范围，并禁用宿主工作目录、
宿主 home、hostfs 及管理员默认 bind-paths 的自动挂载。起始目录为 /tmp。
业务输入通过受权接口或受控只读挂载读取；不得加入任意宿主目录挂载。
--ipc host、特权选项及未登记挂载会明确拒绝；GPU 任务同样使用独立 IPC。

任务仍需通过分配节点的宿主网络访问本地后端，文件与进程隔离不代替接口鉴权。
不要向用户脚本环境注入全数据权限的服务凭据。当前运行方式仍受单一 HPC
操作系统账号约束，不能据此宣称已经获得生产多租户操作系统隔离认证。

## 账号初始化、维护与权限

目标 04 候选使用增量迁移、受控初始化和独立资源授权。新库不能使用历史静态管理员凭据；已有账号和非默认密码按受控升级流程保留。完整命令、六类配置、管理员交接、恢复和回退见[账号与权限操作说明](账号与权限操作说明.md)。

CPU 会话启动器生成该作业的 identity-maintenance-binding.json，将实例与 JAR SHA-256 写入 ready.json 的 identityMaintenance。使用 identity_maintenance_binding.py --describe-job <当前作业号> 核对目标，再调用 accounts.ps1。维护环境文件含数据库密码，权限为 0600，退出时清理；不得打印或上传。新增绑定工具需与 accounts 系列脚本和启动器一起部署。

当前候选原件、私有预览和视图导出通过后端鉴权网关读取。旧版预签名链接须在切换前核对和收敛，不能用旧链接证明撤权。前述历史迁移记录不代替目标 04 当前 JAR、源码/SIF 绑定、十二企业前端或真实入模验收，未通过门槛前不进行正式切换。


当前账号与受控视图候选采用经审核的运行绑定清单。首次部署、更新和回退前请按[运行绑定与发布核验](./运行绑定与发布核验.md)准备并验证 `runtime-bindings.json`；Start 不会自动安装新代码。
