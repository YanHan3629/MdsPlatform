# 同济 HPC 按需测试

本部署是原本地系统的独立测试副本，使用 Singularity 和 Slurm。数据、账号密码、对象、模型、回执和追踪记录已迁移；本地 Docker 服务保持原状。HPC 后续产生的数据不会自动同步回本地。

原本地开发对话继续改进功能前，请先读取 [Codex 开发环境交接](./CODEX_HANDOFF.md)，其中说明源码如何更新到远端、验证范围和数据保护要求；本文侧重日常启停操作。

## 启动、连接、停止

在 `E:\VSCodeProject\MdsPlatform` 的 PowerShell 中操作。需要校园网/VPN及已配置的 SSH 公钥。以下 IP 是本次通过 Xshell 实际连接核实并成功使用的地址；如果以后变更，请使用平台域名或重新核实地址，始终保持 SSH 主机密钥校验。

```powershell
# 完整功能：1张L40、7核CPU、48GB内存；就绪后最多30分钟。
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -Minutes 30 -Server 192.168.212.245

# 使用上一条返回的实际作业号，等待 ready=True。
.\deploy\hpc\session.ps1 -Action Status -JobId <作业号> -Server 192.168.212.245

# 保持这个窗口运行，随后打开下面的浏览器地址。
.\deploy\hpc\session.ps1 -Action Connect -JobId <作业号> -Server 192.168.212.245
```

浏览器地址：<http://127.0.0.1:18888/data-space/index.html>。使用原本地平台的账号和密码登录。预签名对象地址经本机 `19000` 端口访问。不要打开本机原来的 `8888` 地址来判断 HPC 部署效果。

测试结束后，在另一个 PowerShell 窗口执行：

```powershell
.\deploy\hpc\session.ps1 -Action Stop -JobId <作业号> -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Status -Server 192.168.212.245
```

Status 无活动作业后，计算资源已释放。停止会话会中断未完成任务，原始数据和已保存结果保留。**仅关闭浏览器或 SSH 隧道不会取消 sbatch 作业，测试结束请执行 Stop。** 即使忘记停止，会话也有就绪时长和 Slurm 总时长双重上限；总时长额外预留15分钟启动、清理时间。排队截止时间为12小时，不是获配资源后的运行时长。

功能 05 的 GPU 启动在模型身份检查后尝试一次合成文本预热，最长等待约两分钟。`Status` 的 `qaModelWarmup` 和作业目录内的 `qa-model-warmup.json` 记录结果。预热失败时服务仍可就绪，性能测量应单独记录这次预热失败。CPU 会话没有模型预热。

只测数据管理、质量、索引、发布及交付时可选择 `-Mode CPU`：8核、24GB，不启动大模型和问答服务。需要问答时选择 GPU 模式。Start 会阻止同时提交多个本项目作业，避免重复占用资源和打开同一数据库。

默认 `-Server` 为 `logini.tongji.edu.cn`；校园 VPN 与代理分流正常时可以省略该参数。程序不修改 VPN/代理设置，不绕过 SSH 主机密钥校验。计算节点公钥通过已认证的登录连接和自有 Slurm allocation 读取后，才用于建立隧道。

## 功能 05 隔离候选

隔离候选在同济 HPC 的独立工作区运行。登录封面使用同源身份接口，完成服务端校验后恢复允许访问的站内地址。首次登录需要激活时，在封面更改初始密码后重新登录。业务顶栏的“退出所有会话”会立即关闭业务内容。

现阶段可以使用 CPU 隔离候选检查登录。将 `<工作区>` 替换为验收记录中目标 05 的有效绝对工作区路径，连接和停止时使用同一工作区及实际作业号。

```powershell
$candidate = '<工作区>'
.\deploy\hpc\session.ps1 -Action Start -Mode CPU -Minutes 15 -WorkspaceRoot $candidate -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Status -WorkspaceRoot $candidate -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Connect -JobId <作业号> -WorkspaceRoot $candidate -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Stop -JobId <作业号> -WorkspaceRoot $candidate -Server 192.168.212.245
```

已生成 FP8 发布绑定的隔离工作区可以按下面方式启动常规档。此命令在单张 L40、7 核 CPU、64 GiB 主机内存上完成了实际 Edge 文字和图片问答及双路请求检查。

```powershell
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -GpuType L40 -QaProfile standard -Minutes 35 -WorkspaceRoot $candidate -Server 192.168.212.245
```

绑定已验证长文配置的隔离工作区可用以下命令启动。单张 L40、7 核 CPU、96 GiB 主机内存的作业 `3405504` 使用 GPU 常驻 FP8 KV 固定缩放，实测缓存容量为 81,536 token。平台完成 16,413 token 提示的尾段短答、输入和输出超限拒绝，以及 4／8 张合成图依序入模。Edge 读取到 64K 档位和 16,384 token 输出上限。长输出实际消耗、真实多图和业务语义仍在验收。

```powershell
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -GpuType L40 -QaProfile long -Minutes 35 -WorkspaceRoot $candidate -Server 192.168.212.245
```

同济 HPC 的 A800 隔离发布已运行常规和长文档位，均使用单张 A800 和 7 核 CPU。常规档申请 96 GiB 主机内存，长文档申请 112 GiB。候选 `3483891` 使用解码图和原精度 KV，常规档关闭异步调度并使用一枚 MTP 草稿，长文档使用两枚。常规档单路 23 次、双路 24 次合格，P95 分别为 40.110 和 41.000 秒。长文 13 次中 11 次合格，最慢合格请求 54.651 秒。三个性能门槛均达到。双路实际执行并发为 2，满队列与取消恢复通过。两档已完成 80 道开发题的实际执行，独立语义验收待完成。[候选能力配置](../../mdsPlatform/services/qa-service/qa-capabilities.json) [验收记录](../../reports/feature-05-login-qwen38/验收进度.md)

```powershell
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -GpuType A800 -QaProfile standard -Minutes 45 -WorkspaceRoot $candidate -Server 192.168.212.245
.\deploy\hpc\session.ps1 -Action Start -Mode GPU -GpuType A800 -QaProfile long -Minutes 55 -WorkspaceRoot $candidate -Server 192.168.212.245
```

每次选择一个档位，结束后用 Stop 和 Slurm 核对资源释放。含启动前检查的候选在 `runs/<作业号>/qa-cuda-preflight.log` 记录 `cuInit` 和可见设备数。`cuInit=802` 表明 CUDA 驱动初始化尚未完成，应先核对计算节点和已分配设备。候选启动方式适用于显式传入的隔离工作区，正式默认入口当前仍使用原部署。

候选 `3501092` 在单张 A800 上复验常规档。单路、双路各测 28 次，分别有 23、24 次满足完整回答及输入输出计量条件，P95 为 41.652、41.222 秒。双路的两对回答窗口内采样到引擎同时运行两路。标准档在 120.512 秒内生成 7,440 token，240 行合成报告完整按序返回。Firefox 真题的界面答案及引用已与实际网关和模型追踪核对，合成 PDF 的三页也依次实际入模。独立业务语义评分仍待完成。[当前候选验收记录](../../reports/feature-05-login-qwen38/验收进度.md)

同一候选 `3501092` 的 A800 长文档位实测 13 次，12 次符合完整回答和来源计量条件，最慢 57.664 秒。原始 520 行合成报告按序完整返回，耗时 201.420 秒，共生成 16,120 token。16,523 token 的实际提示答出了资料尾段，两项超限请求均返回 422。生成中撤权后，网关在 0.115 秒内拒绝了在途输出。[长文与撤权验收记录](../../reports/feature-05-login-qwen38/验收进度.md)

L40 当前候选的两档均使用 eager 执行，长文档使用固定缩放的 FP8 KV。此前开启原生 MTP 的两档均在真实开发批次中遇到 CUDA 非法内存访问，长文叠加 CUDA Graph 后也复现。当前长文配置的完整输出仍受 300 秒截止时间限制，此前 520 行容量探针返回 504。

## 已验证范围

- 迁移数据库；94,927 个 MinIO 对象的完整清单、大小与快照一致，快照文件本身通过逐文件哈希校验。
- 正常账号登录、主要读取接口；新文件正式上传并逐字节读回；发布冻结快照。
- 后端实际调用 Singularity/Slurm 动态索引任务，输入校验、计算、输出上传、预热、READY 回写通过。
- 真实质量检查；未声明表结构时正确阻止发布，补齐测试数据字段声明后通过发布门禁。
- 消费者未获权时被拒绝；申请、批准、合约确认、真实接收端交付、签名回执读取、交付包与上传原文逐字节一致。
- L40 实际模型生成及文档检索、区域渲染、模型输入和回答链路；模型回答能力错误按用户要求不作为迁移验收阻碍。
- 本机前端和对象存储 SSH 隧道均已实际获得 HTTP 200；停止作业和持久数据再次启动已实际验证。

这些是实际部署的代表性流程验证，不代表穷尽全部业务数据或问答内容。原副本中未完成的索引、失败的质量报告、已过期/撤销的权限保留原状态，不伪造通过。检索选择与模型能力问题分别记录，不能把所有回答错误归因于模型。

## 限制及文件位置

整个服务栈受 Slurm 分配的 CPU/内存上限控制；动态索引另受步骤级CPU/内存限制。进程上限采用用户 UID 范围的硬限制，可能比 Docker 单容器限制更严格。各常驻服务没有逐项复制 Docker Compose 的独立资源上限。当前适用于本账号按需功能测试，不是多租户生产部署。

仅使用本地已转换、登记的 SIF 镜像。任意新 Docker 镜像不能直接运行，需先在有限 Slurm 作业中转换、验证并登记。

- 程序：`~/apps/mds-platform/`
- 镜像与归档：`~/packages/mds-platform/`
- 迁移备份：`~/backup/mds-platform/snapshot-01/`
- 持久数据库、对象、回执、索引缓存：`~/data/mds-platform/`
- 会话日志：`~/apps/mds-platform/session-<作业号>.log`
- 各服务日志：`~/data/mds-platform/runs/<作业号>/`
- 动态任务日志：`~/data/mds-platform/runtime/<作业号>/<容器ID>/output.log`

不要在登录节点启动应用或构建镜像，不使用 Docker daemon、sudo、长期后台服务。传输时无需申请 GPU。历史日志和任务临时目录为便于审计尚未自动清理；测试结束只释放计算资源，不删除持久数据。存储仍受平台配额和计费规则约束。

## 候选运行器的任务隔离要求

更新运行器时，runtime_cli.py、slurm_exec.py 必须来自同一已核验候选版本；
仅替换 JAR 不会同步更新这两个脚本。切换前停止本轮任务，核对两个脚本的哈希，
同时保留上一版本的脚本组合供回退。不要在任务执行中替换运行器。

任务使用独立 PID、IPC、/root 和 /tmp 范围，并禁用宿主工作目录、
宿主 home、hostfs 及管理员默认 bind-paths 的自动挂载。起始目录为 /tmp。
业务输入通过受权接口或受控只读挂载读取；不得加入任意宿主目录挂载。
--ipc host、特权选项及未登记挂载会明确拒绝；GPU 任务同样使用独立 IPC。

任务仍需通过分配节点的宿主网络访问本地后端，文件与进程隔离不代替接口鉴权。
不要向用户脚本环境注入全数据权限的服务凭据。当前运行方式仍受单一 HPC
操作系统账号约束，不能据此宣称已经获得生产多租户操作系统隔离认证。

## 账号初始化、维护与权限

目标 04 候选使用增量迁移、受控初始化和独立资源授权。新库不能使用历史静态管理员凭据；已有账号和非默认密码按受控升级流程保留。完整命令、六类配置、管理员交接、恢复和回退见[账号与权限操作说明](账号与权限操作说明.md)。

CPU 会话启动器生成该作业的 identity-maintenance-binding.json，将实例与 JAR SHA-256 写入 ready.json 的 identityMaintenance。使用 identity_maintenance_binding.py --describe-job <当前作业号> 核对目标，再调用 accounts.ps1。维护环境文件含数据库密码，权限为 0600，退出时清理；不得打印或上传。新增绑定工具需与 accounts 系列脚本和启动器一起部署。

当前候选原件、私有预览和视图导出通过后端鉴权网关读取。旧版预签名链接须在切换前核对和收敛，不能用旧链接证明撤权。前述历史迁移记录不代替目标 04 当前 JAR、源码/SIF 绑定、十二企业前端或真实入模验收，未通过门槛前不进行正式切换。


当前账号与受控视图候选采用经审核的运行绑定清单。首次部署、更新和回退前请按[运行绑定与发布核验](./运行绑定与发布核验.md)准备并验证 `runtime-bindings.json`；Start 不会自动安装新代码。
