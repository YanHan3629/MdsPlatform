# HPC 企业账号与权限操作

适用于含企业权限迁移、运行绑定 V2 和 Windows 账号维护脚本的同济 HPC 发布包。本说明按 R332 候选的脚本、接口和初始模板核对。完整上线验收以同一版本的实际账号、浏览器、权限矩阵和模型记录为准。

## 首次管理员

在 Windows PowerShell 7 中进入发布包的 HPC 脚本目录，准备 Python 3 和已配置主机密钥的 OpenSSH。先按[启停说明](./使用说明.md)用 `-Mode CPU` 启动所选实例。全新部署使用空快照，管理员维护走 SSH 及当前已就绪的自有 CPU Slurm 作业内的受控入口。需要 GPU 问答时，完成初始化和登录验证，停止 CPU 作业并确认释放，再用同一工作区启动 GPU 作业。

对独立工作区，输入本次 Start 返回的工作区和实际作业号。脚本从当前就绪记录取得维护目标。

```powershell
$workspace = Read-Host '独立工作区路径'
$jobId = [int](Read-Host '当前 Slurm 作业号')
$status = & .\session.ps1 -Action Status -JobId $jobId -WorkspaceRoot $workspace
if (-not $status.ready -or $status.identityMaintenance.jobId -ne [string]$jobId) {
    throw '等待当前实例就绪后再执行'
}
$target = @{
    JobId = [string]$jobId
    Server = 'logini.tongji.edu.cn'
    User = Read-Host 'HPC SSH 用户名'
    WorkspaceRoot = $workspace
    Instance = $status.identityMaintenance.instanceId
    Database = $status.identityMaintenance.database
}
& .\accounts.ps1 -Action Inspect @target
```

核对工作区、实例、数据库和运行中的 JAR，确认这是全新且未初始化的部署后执行下列命令。按提示输入管理员用户名，两次交互输入密码。

```powershell
& .\accounts.ps1 -Action BootstrapAdmin @target
```

预期结果为 `INITIALIZED`。用新账号从浏览器登录并打开“账号与权限管理”，检查账号与业务类型列表。重复执行应返回 `ALREADY_INITIALIZED`。若命令中断，用同一个作业号重新执行 `Inspect` 并核对事务结果。

## 旧库升级与管理员恢复

1. 保存部署版本、数据库备份、对象清单和既有合同及授权基线。先用独立副本验证升级。Flyway 按发布包执行增量迁移。
2. 在确认的未初始化旧库中，选择需要保留的既有管理员账号 UUID。先用 `Inspect -TargetUserId` 核对目标，再执行 `UpgradeAdmin`。有自设密码的账号通过交互输入原密码来证明身份，原密码继续有效。使用公开种子凭据的目标须设置新密码。旧角色名称本身无权授予平台管理员资格。
3. 验证选中的账号可登录并执行管理操作，确认其他旧角色成员的有效能力、企业映射、受控视图和旧合同范围。升级可能需要复核用户的业务类型及组织归属。

```powershell
$userId = Read-Host '已审核的既有管理员账号 UUID'
& .\accounts.ps1 -Action Inspect -TargetUserId $userId @target
& .\accounts.ps1 -Action UpgradeAdmin -TargetUserId $userId @target
```

已初始化实例需要恢复时，先批准维护窗口，核对受影响实例和既有管理员 UUID。使用 `EnterMaintenance` 开启维护模式，再恢复指定账号。恢复会设置新密码并撤销目标的旧会话。组织也需恢复时，单独审核组织状态，再决定是否给恢复命令加 `-ReactivateOrganization`。确认操作结果后退出维护模式，登录验证并核对审计。

```powershell
$userId = Read-Host '需要恢复的既有平台管理员 UUID'
& .\accounts.ps1 -Action EnterMaintenance @target
& .\accounts.ps1 -Action RecoverAdmin -TargetUserId $userId @target
& .\accounts.ps1 -Action Inspect -TargetUserId $userId @target
& .\accounts.ps1 -Action ExitMaintenance @target
```

密码从交互提示输入。脚本参数、证据记录和审计只使用标识、状态及必要的校验信息。

## 成员、业务类型和管理员

- 平台管理员从“账号与权限管理”选择企业，创建普通成员、分配主业务类型和附加岗位。新账号按首次登录提示更换初始密码。企业成员管理者在本企业及获委托的类型范围内操作。
- 个人在“我的账号”改密、退出或输入用户名确认注销。管理员可停用、恢复、重置密码、强退或注销成员。停用后须执行恢复流程，注销是终态，业务对象和历史审计可追溯。创建账号时应核对用户名保留规则。
- 业务类型编辑从权限树选择操作，再核对影响预览和确认。删除有成员的类型时选择合法替代类型并审阅迁移。将成员改为只读时替换主配置，并先移除冲突的写入或导出岗位。操作能力、资源授权和管理资格分别核对。
- 含 R519 扩展的候选在预览中列出计算／索引执行、自动索引队列和质量检查；任务状态变化后重新预览。企业成员管理者不会看到迁入成员在原企业的任务编号。渲染、问答和交付仍需另行核对，详见[身份变更审阅协议](./身份变更审阅协议.md)。此扩展尚未完成真实 Edge 验收和正式切换。
- 管理员交接时先授予接任账号平台管理员资格，使用接任账号实际登录并核对管理能力，再处理原管理员。停用、注销、撤销资格和关联变更均受最后有效平台管理员约束。
- 改密、重置、停用、注销和影响现有权限的变更后，重新核对身份及有效能力。前端清理旧会话数据，服务端按当前主体、版本和范围检查新请求。

初始模板可编辑。六类业务模板共用本范围目录、预览、检索、问答、受控视图导出、创建上传、草稿、质量详情、提交消费申请、本方合同和回执以及本范围任务能力。表内附加能力仍需具体资源授权。

| 初始模板 | 治理、发布版本和索引 | 产品发布及供给审批 | 完整原件下载能力 |
|---|---|---|---|
| 制造 `MANUFACTURER`、供应 `SUPPLIER` | 有 | 有 | 有 |
| 仓储 `WAREHOUSE`、承运 `CARRIER`、安装售后 `SERVICE` | 有 | 按岗位分配 | 按岗位分配 |
| 客户渠道 `CUSTOMER` | 按岗位分配 | 按岗位分配 | 按岗位分配 |
| 只读 `READ_ONLY` | 关闭 | 关闭 | 关闭 |

只读模板保留授权目录、预览、检索和问答。

平台管理员管理身份和配置，企业成员管理者管理受托普通成员，合约经办人代表本企业确认或撤销合同。业务读取仍须有效资源授权。对外协作岗位应从已实现的操作代码选择。

## 资源授权、撤销和接口

公开摘要是已发布且获准展示的产品信息。受控视图是授权行列或片段物化后形成的冻结版本和索引。完整原件须对完整文件另行获得下载权限。受控视图导出和合同交付各自检查授权动作和范围。

新建公开产品或将内部产品转为公开时，描述留空会使公开摘要保持为空。重发已经公开的产品时，留空会沿用该产品现有的公开摘要。仅在组织内发布时，描述留空可沿用源目录说明。

分享时选择企业或成员、具体冻结资源、操作、用途和有效期，核对预览后确认。对混合数据按受控视图授权。撤销先核对授予主体、目标和影响，再确认撤销，复核旧地址和新请求均遵循当前授权。已签名的历史回执可按审计权限核验。历史回执的重读和重新交付使用独立决策。

已开始的文件下载可能在撤权前返回 HTTP 200。传输中断时按声明长度和文件校验值判断下载是否完整，接收方可能已收到撤权前发出的字节。质量任务在读取中断或授权失效时停止提交测量结果。撤销原发起人会话或质量服务授权后，核对任务状态 `FAILED`、原因 `QUALITY_ORIGINAL_AUTHORITY_REVOKED` 及发布计数。恢复授权后，如仍需测量，使用当前授权新建任务。

| 能力 | 当前入口和主要操作代码 |
|---|---|
| 账号和能力 | `GET /api/users/me`、`PATCH /api/users/me/password`、`POST /api/users/me/close`、`POST /api/auth/logout` |
| 成员与管理资格 | `/api/identity/users` 及其 `types`、`state`、`password-reset`、`close`、`qualification` 子入口。能力为 `identity.member.*` 和 `identity.platform-admin.manage`。 |
| 类型与变更影响 | `/api/identity/operations`、`/api/identity/types` 和 `/api/identity/changes/{id}`。类型维护使用 `identity.type.manage`。 |
| 明确资源授权 | `POST /api/identity/resource-grants/preview`、`POST /api/identity/resource-grants/{grantId}/revoke-preview`、`POST /api/identity/resource-grants/reviews/{reviewId}/confirm` |
| 数据搜索、问答及导出 | `POST /api/data-space/qa/search`、`POST /api/data-space/qa`、`GET /api/data-space/controlled-views/{viewId}/{versionId}/{indexVersionId}/export`。能力为 `data.search`、`data.qa`、`data.view.export`。 |
| 供给与消费 | `/api/data-space/sources`、`/api/data-space/products`、`/api/data-space/intents`。逐项核对 `dataset.upload`、`dataset.publish`、`product.publish`、`application.submit`、`application.review`。 |
| 合同与交付 | `/api/data-space/contracts`、`/api/data-space/deliveries`。确认、撤销、执行、回执和包下载分别使用 `contract.confirm`、`contract.revoke`、`delivery.execute`、`delivery.receipt.read`、`delivery.package.download`。 |

既有明确授权的 `FULL_VERSION` 合同按签署时的范围复核。将旧合同改成受控子集需要列明范围差异、受影响主体及迁移方案，再按业务变更审批执行。

## 异常与回退

| 现象 | 排查步骤 |
|---|---|
| 401 | 核对实例与会话。账号、密码或类型刚变更时重新登录并查看当前有效能力。 |
| 403 或对象不可见 | 逐项核对账号及企业状态、操作、冻结版本、用途和授权期限。 |
| 版本或预览冲突 | 重新读目标当前状态，生成新影响预览，再确认。 |
| 确认受控视图发布时响应超时 | 用审阅返回的 `publicationId` 查询 `GET /api/controlled-view-publications/{publicationId}`，核对发布状态和索引回执。仍在索引时继续观察同一发布。若进入失败状态，保留原记录并按发布流程创建替代版本。 |
| 未就绪或账号维护拒绝 | 核对 Slurm 终态、工作区、运行绑定、实例 ID 和数据库。用相同目标重查 `Inspect`。 |
| 最后管理员保护 | 先创建并验证接任的有效平台管理员，再重新提交变更。 |

发生需要回退的版本问题时，先在获批维护窗口隔离入口并确认受影响工作区。保留现有候选、数据库与对象状态以及审计记录。用相匹配的旧代码、迁移前数据库备份和对象清单在独立副本恢复，核验账号、授权、历史合同、冻结版本和资源访问后，再决定是否切换。结束测试后执行同一工作区的 Stop 和 Status，另查 Slurm 确认释放。
