# 账号、权限与企业视图操作说明

适用于目标 04 的完整候选版本。先核对当前作业、JAR、运行器和实际加载的服务源码。旧部署不会自动获得本文功能；本文不声明正式部署已完成切换。

## 权限与默认配置

一次业务请求必须同时满足：账号与企业有效、操作配置允许、一个完整有效授权覆盖资源与动作、版本/用途/合同/有效期成立。相同企业、产业链类型、创建者或平台管理员身份不能替代资源授权；不能拼接授权 A 的动作和授权 B 的文件。

制造、供应、仓储、承运、客户/渠道、安装/售后六类配置均需具体资源授权。业务 ENT-* 与登录组织 orgId 分开管理，必须核对当前目录并确认映射；确认映射本身不授予数据。

| 操作 | 默认配置 |
| --- | --- |
| 目录、预览、检索、问答、授权视图导出 | 六类均有操作能力，仍需授权范围 |
| 创建、上传 | 六类均可，仅本方获准范围 |
| 治理、发布版本、构建索引 | 客户需追加数据维护配置，其他五类默认可 |
| 发布产品、审批供给申请 | 制造、供应默认可，其他四类需供给管理配置 |
| 完整原件下载 | 制造、供应默认有操作能力，仍需完整文件授权；其他四类默认关闭 |
| 确认/撤销合同、接收端、交付 | 六类均需显式经办/交付配置和资源授权 |
| 管理账号、类型、平台管理员 | 六类均默认关闭，单独配置受保护资格 |

只读使用者是替换业务成员操作集合的完整配置，不是追加空角色。清除冲突岗位并核对最终能力；只读者不上传、修改、发布、下载原件、导出或确认合同。平台管理员与企业成员管理者分开显示，后者只能管理本企业及其可授予类型。

## 首次初始化管理员

初始化经已认证 SSH 进入当前 CPU Slurm 作业，没有匿名初始化入口。本机不启动应用，登录节点不运行 Java 或访问数据库。密码由交互输入，不写入参数、脚本、历史、日志或报告。

先成套部署当前 JAR、serve.py、identity_maintenance_binding.py、accounts.ps1、accounts.py、accounts_control.py、accounts_compute.py 和配套运行器。启动器生成当前作业的私有绑定；它核对实例、数据库、Java 和 JAR SHA-256。含数据库密码的维护环境文件权限为 0600，作业目录为 0700。

按 HPC 使用说明启动有限 CPU 会话并记录实际作业号。先识别目标，再检查状态并初始化：

~~~powershell
$hpcServer = 'logini.tongji.edu.cn'
$hpcUser = 'u08162'
$hpcJob = '<实际 CPU 作业号>'
$remoteApp = '/share/home/u08162/apps/mds-platform'
$target = ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o 'HostKeyAlias=[logini.tongji.edu.cn]:10022' -p 10022 "$hpcUser@$hpcServer" "python3 $remoteApp/identity_maintenance_binding.py --describe-job $hpcJob" | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or $target.success -eq $false) { throw '未取得当前已核验目标' }

.\deploy\hpc\accounts.ps1 -Action Inspect -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp
.\deploy\hpc\accounts.ps1 -Action BootstrapAdmin -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp
~~~

交互输入用户名和两次新密码。成功返回 INITIALIZED，重复调用返回 ALREADY_INITIALIZED，不覆盖账号或密码。并发初始化由数据库事务锁控制。旧静态种子凭据不可登录，历史 V1 迁移保持原样，由增量迁移和登录门禁处理。

连接当前作业的隧道后访问 http://127.0.0.1:18888/data-space/index.html。创建第二名平台管理员，让其完成激活并实际验证管理能力，再交接职责。初始用户名没有永久豁免；最后一名可登录管理员不能被普通操作删除、停用、降权或间接失效。

## 已有部署升级与凭据恢复

升级前保存当前数据库、授权和对象基线。ADMIN、SUPER_ADMIN、ORG_ADMIN 名称不自动证明平台管理资格；逐账号确认实际职责，通过受保护资格定义生效。不要清库、重跑首次迁移或重放 snapshot-01。

进入维护模式后，对明确的旧账号调用 UpgradeAdmin。非默认密码由操作者验证并保留；已知种子凭据需设置新密码。已有部署不重跑首次初始化。

~~~powershell
.\deploy\hpc\accounts.ps1 -Action EnterMaintenance -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp
.\deploy\hpc\accounts.ps1 -Action UpgradeAdmin -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp -TargetUserId '<已核对的旧账号 UUID>' -ReasonCode PLANNED_LEGACY_ADMIN_REVIEW
~~~

管理员全部失效或遗忘密码时，在维护模式中调用 RecoverAdmin，指定目标并交互输入新密码。恢复撤销旧会话并留存审计；确需恢复所属组织时显式添加 ReactivateOrganization。恢复不会自动退出维护模式：

~~~powershell
.\deploy\hpc\accounts.ps1 -Action RecoverAdmin -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp -TargetUserId '<已核对的账号 UUID>' -ReasonCode CONTROLLED_ADMIN_CREDENTIAL_RECOVERY
.\deploy\hpc\accounts.ps1 -Action ExitMaintenance -JobId $hpcJob -Server $hpcServer -User $hpcUser -Instance $target.instanceId -Database $target.database -RemoteRoot $remoteApp
~~~

退出维护模式后验证新凭据和管理页面。目标不符、作业不属于本人、不是运行中的 CPU 作业、配置不私有或 JAR 不符时停止，不绕过校验。正常退出和启动失败都清理本作业的维护凭据文件；稳定实例标识留给后续会话核对。不要打印私有环境 JSON 排障。

## 账号、类型与管理员日常管理

在“账号与权限”创建成员，选定已确认企业和有效类型，核对最终操作。临时密码仅交给受控使用者，首次登录激活并改密。“我的账号”提供改密、退出所有会话和注销。停用与注销分开；恢复停用账号不恢复旧会话，普通恢复按钮不复活已注销身份。

类型支持创建、改名、调整操作、停用和删除。未知操作、保留管理代码和 ROLE_ 命名变形被拒绝。带成员类型先迁移成员或使用接口支持的受控替代方案，不能删除后回退成通用权限。提交使用当前版本；发生冲突时重新读取并审核差异。

影响预览显示通用计算与索引执行、自动索引队列、质量检查、问答和区域渲染的请求编号及当前状态。任务状态变化后，请重新生成预览。企业成员管理者仅能看到本企业的任务。出现「状态待核实」时，请先核对原请求和工作器状态。独立交付依据机构授权运行，确认前请核对合同和交付任务。覆盖范围与接口字段见[身份变更审阅协议](./身份变更审阅协议.md)。

平台管理员资格经专门流程增删，不能通过自定义类型名称取得。尚未激活的新管理员不能成为唯一接替者。企业成员管理者不能管理其他企业、平台资格或全局类型。

改密、重置、退出所有会话、停用与注销影响服务端会话及派生任务凭据。页面若提示“服务端退出未确认”，只能确认本地清理，不能声称旧令牌已撤销。关闭身份保留企业数据、合同、回执和审计引用，用户名与主体 ID 不混用。

管理 API 的 `POST /api/identity/users/batch-close` 可按明确名单批量注销。请求提交 `confirm: true` 和 `accounts`，其中每项为用户的 `userId` 与当前 `expectedVersion`（来自账号列表的 `permissionVersion`），每批 1 至 50 个不同账号。服务端逐个校验管理范围和版本；任一账号不符合条件，或整批会使最后一名有效平台管理员失效，整批回滚。成功只关闭这些身份并逐条留审计，企业数据和历史记录继续保留。

## 企业责任视图与文件分享

综合数据集由明确保管主体按当前 VIEW_BUILD 授权使用，原始快照保持不可变，不重新归属某家模拟企业。分享页面支持：

- 按接收企业业务责任范围生成：后端从已确认目录确定企业，固定规则选择记录、参与方字段、JSON 集合和可见表格，公式只在保留范围计算。
- 逐文件选择行列：明确主键、行、列或集合范围；已有 READY 父视图只能从其物化内容继续选择，不能借此扩大到主库。

完整 PDF、图片、SVG、OBJ、STEP 或 TXT 需逐件明确提出分享，核对全部记录、隐藏内容、元信息和依赖后再批准。归属清单不能代替内容审核。部分行列权限不能打开混合主表原件；无 RAW 权限的成员不能查看或复制完整原件。

先生成私有预览，逐项核对实际文件、字节、目标企业和范围，再审核并确认发布。预览不自动授予接收方权限。实际原生构建、产物校验和预热完成后才成为 READY；导出只包含授权子集、范围说明与版本。

READY 只表示构建完成。到期、撤销、来源授权代次变化或企业和账号失效后，后续读取按当前状态重新校验。已经送达的字节无法收回。

授权到期后，在“资源授权与分享”中重新核对接收方、冻结版本和索引、操作、用途和新有效期。原冻结视图及其来源仍有效时，由具备当前分享权限的提供方预览并确认一条新授权。合同约定的范围和期限仍须满足。若需要调整可见数据或来源已失效，先按受控发布流程审核并构建新的冻结视图。确认后，用接收方验证新授权，并用未获授权的同类企业复测拒绝。

## 能力、接口与兼容范围

操作代码定义在 OperationCatalog，固定控制器映射在 EndpointOperationCatalog；同目录“权限接口映射.json”列出当前候选控制器的实际路由、固定能力和声明的附加管理校验。身份接口仍需服务层状态、资格、企业与可授予范围判断。操作映射不代替资源授权。

| 入口或处理器 | 主要操作 |
| --- | --- |
| 账号与类型管理 | identity.self.*、identity.member.*、identity.type.manage、identity.platform-admin.manage 等对应资格 |
| /api/identity/resource-grants | 平台配置使用 identity.resource.manage。提供方分享使用 dataset.share.manage，并须持有覆盖所选范围、操作和期限的有效来源授权。新增和撤销均先预览，再确认。 |
| /api/mm/**、/api/artifacts/** | dataset.create/upload/draft.manage/publish；读取区分 data.catalog.read 与 data.raw.download |
| /api/controlled-view-proposals、previews、publications | dataset.share.manage，私有预览另查完整来源授权 |
| /api/data-space/controlled-views | data.view.export 加当前受控视图授权 |
| DataSpaceQaController | data.search 与 data.qa 分开，source 用 data.raw.download |
| QaEvidenceController | data.preview 加具体证据/来源范围 |
| DataSpaceQualityController | dataset.quality.run、dataset.quality.read |
| DataSpaceFlowController 合约/交付处理器 | contract.* 与 delivery.* 分开 |
| /api/jobs/** | job.read/log.read/cancel；通用运行管理另需 platform.runtime.manage |

JOB_IO、EVIDENCE_IO 不是全数据令牌。任务、运行、冻结输入输出、路径、来源授权代次及当前主体一起校验，旧未绑定来源的 EVIDENCE_IO 不能兼容放行。用户任务与独立企业服务主体分开；服务主体需自己的操作、合同和资源授权。

既有 `FULL_VERSION` 合同保留已确认的冻结全版本范围。定时交付要求同一历史修订明确保留 `CONTROLLED_DELIVERY` 用途下的原件读取、导出和交付包下载权限。工作器在打包和发送期间持续核对合同有效性、冻结文件和来源授权。确认时若返回 `LEGACY_FULL_VERSION_DELIVERY_SCOPE_REQUIRED`，需先为拟交付的冻结版本发布受控视图，再发起受控合同。变更历史合同前，列出原范围、拟变更范围及受影响主体，再按合同流程处理。

## 失败处理和回退

401 表示身份或会话失效；重新登录不恢复旧授权。403 先核对操作/资格，不能追加管理员绕过读取。404 不通过更换 orgId、对象地址或内部令牌枚举。409 重新读取当前状态并审核，不重复覆盖。

旧版本已经发出的 MinIO 直连签名由对象存储校验。上线前核对实际签发期限和存储访问策略，使用隔离样本分别验证旧直连地址失效、现行鉴权网关在撤权后拒绝，以及其他合法读取仍可用。记录状态码和时间，签名链接本身留在隔离验证环境。涉及生产签名凭据或对象存储策略的调整，由运维确认影响和回退步骤后执行。

构建失败或仍在 BUILDING 时保留日志、步骤退出码、产物校验和回调状态；上传数不代表 READY。控制库不可用时停止受保护读取和输出，不能使用旧缓存放行。

切换前停止本轮任务，核对成套代码、JAR、运行器、实际 SIF 和源码绑定，完成账号、组织、数据、合同、授权及回执前后核对。回退先进入维护模式，恢复匹配的代码和数据库，再验证权限；旧程序不了解新模型时不能只换旧 JAR 继续开放。清理只处理明确记录的本轮对象。

本文不声明生产多租户操作系统隔离认证，也不声明十二企业前端、全格式模型或全部撤权边界已通过。正式切换前以完整验收证据确认门槛。


## 受控标准输入调用

`accounts.ps1 -RequestStdin` 将调用方提供的 UTF-8 JSON 字节通过标准输入交给现有 Python 控制端，仍需显式指定 Action、JobId、Server、User、Instance、Database 和部署目录。脚本不把 JSON 或口令放入命令行、PowerShell 数据管道对象或临时文件；Python、SSH 控制端和计算节点仍逐级校验目标实例及数据库，并执行原有严格字段、长度与确认校验。

普通人工运维继续使用默认安全交互方式。自动调用方必须在受保护进程中生成或接收一次性输入，通过进程标准输入写入后关闭输入流；不得在终端命令中粘贴带口令的 JSON，不得启用请求正文记录或转录。失败及超时后先核对原作业、初始化状态和审计，再决定是否重试，避免把未知结果当作未执行。业务初始化、升级和恢复规则与交互方式相同。
