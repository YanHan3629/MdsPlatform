# 身份变更影响审阅

类型定义修改／删除、账号类型分配、管理资格修改、账号名称／组织／类型修改必须先预览，再明确确认同一请求。新建类型和新建普通账号沿用现有接口。原版本比较、管理范围、最后可登录管理员保护继续生效。

| 变更 | POST 预览地址 | 应用地址 |
| --- | --- | --- |
| 账号资料／组织／类型 | `/api/identity/users/{uid}/impact` | `PATCH /api/identity/users/{uid}` |
| 账号类型分配 | `/api/identity/users/{uid}/types-impact` | `PUT /api/identity/users/{uid}/types` |
| 管理资格 | `/api/identity/users/{uid}/qualification-impact` | `PUT /api/identity/users/{uid}/qualification` |
| 类型定义 | `/api/identity/types/{id}/impact` | `PUT /api/identity/types/{id}` |
| 类型删除和替代迁移 | `/api/identity/types/{id}/delete-impact` | `POST /api/identity/types/{id}/delete` |

预览和提交的 JSON 结构相同，包含当前 `expectedVersion`。预览响应包含 `review_id`、`review_sha256`、`expiresAt`、`canApply` 和 `impact`。每个受影响账号的 `before`／`after` 包含企业、类型、资格、委托类型、配置操作与当前有效操作。任务只列排队／运行的持久化用户任务标识、状态及权威来源类别；不返回命令、文件内容或凭据。无替代类型时仍可查看删除影响，`canApply=false` 会解释阻断原因。

`tasks` 中的 `taskKind`、`taskId` 和 `status` 区分以下记录：

| `taskKind` | 标识与范围 |
| --- | --- |
| `EXECUTION` | 通用计算或原生索引的 `runId`，同时保留原来的 `runId`、`jobId` 字段。 |
| `INDEX_QUEUE` | 自动索引队列的 `task_id`，包含排队、重试、处理和等待索引完成的阶段；已由活动执行记录表示的队列项不重复列出。 |
| `QUALITY` | 质量报告的 `report_id`，包含排队及已经通过正式服务接口领取的任务。 |
| `QA_REQUEST` | 问答后台调用标识，绑定实际发起账号、企业和 ACCESS 父会话。 |
| `RENDER_REQUEST` | 区域渲染后台调用标识，绑定实际发起账号、企业和 ACCESS 父会话，并校验证据范围。 |

问答和区域渲染活动记录使用增量迁移 V42。`impact.directTaskCoverage` 声明上述五类记录的覆盖范围。`allTaskKindsCovered=false` 时，独立交付和未确认响应对应的下游工作器需另行核对。任务状态变化会使原审阅失效，提交返回冲突后需重新生成预览。

问答、渲染记录只保存账号、企业、父会话、令牌版本、请求类别、状态和时间等管理元信息，不保存问题、回答、提示词、原件或令牌。有效租约显示 `RUNNING`；连接中断、未确认的响应或租约失效显示 `UNCONFIRMED`（状态待核实），不会因超时自动宣称工作器已经停止。这些记录不能授予任何业务权限。

已明确收到并处理的后台响应结束活动记录，失败响应保留 `FAILED`，成功响应保留 `SUCCEEDED`。这里的成功仅表示该后台调用及相应本地校验完成；最终向用户返回数据仍须经过原有输出授权复核。未确认记录在重启后继续可见，管理员应核对其原作业和服务状态，不能把它当成可重发业务请求的依据。

企业成员管理者只能看到本企业的任务标识。成员迁入本企业后，原企业的任务仍保留在内部审阅快照中，但不会出现在新企业管理者的预览和重新读取响应中。内部快照及审阅哈希不因响应裁剪而改写；平台管理员仍可核对完整管理元信息。

提交保留预览时的 JSON，并同时设置：

```http
X-Identity-Review-Id: <review_id>
X-Identity-Review-Sha256: <review_sha256>
X-Identity-Review-Confirm: true
```

每项头部只能出现一次。服务端不接受跳过审阅参数。缺少头部返回 428；头部格式错误返回 400；审阅不存在或属于其他主体返回 404；过期、已取消／提交、请求改变、版本或快照改变返回 409。原业务校验可能先拒绝无权限、版本冲突或无效请求。

审阅在 10 分钟后过期。它绑定创建人、所属企业、令牌版本、权限版本、全局策略版本、完整请求及影响快照。账号登录、任务状态或任何相关状态变化可能使它失效，需要重新预览。提交在统一身份锁和权威事务锁中重新计算影响；实际写入后还核对真实授权结果、分配、资格和会话撤销。核对失败时整个数据库变更和审阅消费一起回滚。

`GET /api/identity/changes/{id}` 只能由创建人且仍在当前管理范围内读取。取消使用 `POST /api/identity/changes/{id}/cancel`，请求为 `{"reviewSha256":"<review_sha256>"}`；取消与提交互斥。历史记录和审计不被覆盖、删除或改写。审阅表只保存管理元信息，不保存密码、哈希密码、令牌或业务内容。

旧角色接口沿用同一守卫与事务。对应预览为 `POST /api/roles/{id}/impact`、`POST /api/roles/{id}/permissions/impact` 和 `POST /api/roles/{id}/delete-impact`。分别使用原 PATCH 角色请求、权限 UUID 数组加 `If-Match`，以及原删除请求的 `If-Match` 和替代类型查询参数。预览后向原修改／删除接口提交同一内容和三个审阅头部。仅持旧客户端写入权限而未提供审阅证明时不能变更。

类型变化同时影响直接成员和获委托分配该类型的企业管理者；双方旧会话都撤销。被使用或委托的类型删除需要有效替代类型，原子迁移直接分配、主类型与委托列表。检查完整迁移后岗位组合，拒绝只读主类型与写入／导出附加岗位冲突。被委托的只读、写入类型是可供分别选择的选项，允许同时委托；实际为成员分配组合时仍按组合校验。

审阅展示操作能力变化；具体数据仍需原资源授权、用途、版本和有效期。审阅本身不授权数据，也不证明所有后台任务已停止。现有任务继续经过各自的实时权威复核与撤销流程。完整运行中撤权时限、独立交付和浏览器人工验收需保留各自的实测证据。

部署时构建候选 JAR，在私有数据库验证 V31 审阅迁移及 V42 请求活动迁移，再执行真实接口验收和运行绑定核验。正式切换前先备份并核验正式账号与业务记录。回退步骤见[账号与权限操作说明](./账号与权限操作说明.md)。
