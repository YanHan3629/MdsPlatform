# 通用任务的冻结输入输出

适用：普通用户派生的通用任务。索引构建及受控视图预览继续使用各自的专用权威流程。平台运行能力不产生业务数据读取权。

任务创建／修改沿用 `/api/jobs`。每项 `inputs` 现在可提供可选 `commitId`：

```json
{
  "repoId": "仓库 UUID",
  "commitId": "该仓库已发布快照 UUID，可省略",
  "paths": ["/指定文件.csv", "/指定目录"]
}
```

省略 `commitId` 时，在运行启动事务中选择该仓库的最新已发布快照。提供时会持久保存并校验所属仓库及已发布状态；重启或仓库 HEAD 变化不会改变该选择。重复声明同仓库时快照选择必须一致；路径合并，任一空路径列表表示仓库全选。旧的单仓库 `MDS_INPUT_REPO_ID`／`MDS_INPUT_COMMIT_ID` 参数保留，不能与声明冲突；多仓库分别使用 `inputs[].commitId`。

所有声明输入、选择路径、输出草稿和各自原始授权均进入不可改写的运行定义。每个输出都在同一启动事务中解析到已授权草稿。同一草稿已有排队／运行任务时返回 `409 JOB_OUTPUT_DRAFT_HAS_ACTIVE_EXECUTION`，不能并发覆盖该草稿。新的声明、失败启动及资源参数继续受既有事务与额度控制。

普通任务使用 `job-execution-definition-v2` 和 `job-io-manifest-v1`。工作器用原 `JOB_IO` 凭据访问 `GET /api/jobs/{jobId}/io-manifest`，只能取得自身当前运行的清单。普通 ACCESS 凭据不能借用此入口。清单 SHA-256 同时绑定于冻结定义、任务凭据及服务端提供的工作器环境；客户端传入的同名环境字段会被移除。

清单中的每个输入包含 `repoId`、`commitId`、`paths`、`primary`、`localPath`；输出包含对应仓库、草稿、主项标志和目录。目录规则为：

| 项目 | 目录 |
| --- | --- |
| 原有主输入 | `/tmp/in` |
| 其他输入 | `/tmp/inputs/{repoId}` |
| 原有主输出 | `/tmp/out` |
| 其他输出 | `/tmp/outputs/{repoId}` |

用户程序通过环境 `MDS_JOB_IO_MANIFEST=/tmp/job-io/manifest.json` 查看全部映射，保留 `INPUT_DIR`、`OUTPUT_DIR` 兼容入口。每个输入的完整文件清单位于 `/tmp/job-io/input-manifests/{repoId}.json`。旧 `files.json`／`files.tsv` 便利入口仅在不覆盖同名业务文件时生成；新程序应使用独立清单目录。

所有输入在用户代码执行前完成分页读取及总数核对，按每个仓库自身的选择器下载并验证路径、存在性、大小和 SHA-256。任一必需输入、清单身份或入口脚本校验失败时，不执行用户代码，不上传任何输出。目录选择不会使另一个仓库或未选文件进入可读范围。

全部输出目录在首次上传前整体检查。路径遵守现有 Unicode 字母／组合标记／数字及 `._-` 白名单和长度限制，拒绝路径穿越、符号链接和非普通文件。用户代码失败时不上传。每次读写仍由服务端重新检查任务、原始会话、操作能力和原始完整资源授权；不能拼接两份授权的动作与范围，也不能在原始授权失效后自动换用另一份授权。

索引仓库输入另外要求：当前主体属于数据所有企业，同时拥有 `data.raw.download` 与 `dataset.index.build`，并有一份覆盖两项操作、精确资源及 `VIEW_BUILD` 用途的当前授权。工作器请求、历史凭据复核、普通索引文件读取和相关任务元信息均保持索引权限边界。平台管理员资格或仅有原件读取能力不能自动取得索引内容。

已有 v1 通用任务凭据保留原主输入／输出范围，不因新增清单扩大权限；索引输入额外能力也在旧记录复核中执行。专用索引／预览凭据继续由各自原始运行、会话、授权和固定坐标验证，不能通过通用任务声明冒充。

通用上传结束后仍为草稿；传输中途失败可能留下未发布的部分文件。不得将任务失败、部分文件或 `READY` 文件行当作全部输出成功或正式发布。任务完成和后续发布、交付中的原始授权传播，仍需对应业务门禁与验收；本协议不宣称所有下游路径已完成。

当前证据包括真实多仓库执行、固定快照重启／HEAD 变化、独立对象字节核对、缺失第二输入停止、原主目录兼容、真实任务影响预览与撤权。读取索引文件的通用任务只是一种通用变换任务；质量、索引构建、渲染、问答、独立交付及长输出流的撤权边界需要分别验证。Windows Edge 全业务验收、完整启动器及正式切换仍需各自通过门禁。
