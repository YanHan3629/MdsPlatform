# 经审阅转授授权的原始来源约束

业务转授固定引用一份完整原始授权的 ID、代际及用途。每次业务操作，在账号、资源、合同和有效期校验之外，逐级核验本次步骤所需的完整动作集合及分享能力。撤销或替换原始授权不会让旧转授自动改用新授权；当前请求不需要的日志、检索或问答动作不应阻断仍获准的其他操作。

每级转授人的当前身份及所需操作能力必须有效。原授权的主体、企业、数据集、冻结版本／索引、视图代际、用途和期限须覆盖下一级。合同仍须是同一当前修订，覆盖本次所需动作及用途。新建转授时须覆盖全部拟授予动作；使用时按实际步骤所需动作核验。缺失、无法解析、循环或超过 32 次转授的链拒绝使用，新增转授在审阅和入库时受同一上限约束。

平台管理员在同一数据所有企业内明确配置的授权是独立机构配置，不因配置管理员之后退出登录而自动删除。业务转授不借用转授人的登录令牌；用户派生任务自身仍须满足原会话、运行和冻结凭据约束。没有来源记录的历史明确授权保留原范围与已有校验，不伪造来源。

授权管理页分别显示本条状态、期限、完整来源约束和来源支持的动作。来源动作可能部分失效，实际访问仍须满足当前账号能力、资源、用途及合同。撤销预览显示当前代际链的下游授权记录、接收主体数量及引用来源的排队／运行通用任务；此处的通用任务信息不代表所有其他任务类型均已纳入影响验收。

普通完整授权读取和父视图来源检查均使用本次实际动作集合。质量、原生索引、渲染、问答、独立交付、持续输出、并发及不可用／恢复仍须分别完成真实撤权验证。完整 Windows 前端与最终运维切换也须单独通过门禁。旧 JAR 缺少此来源约束，回退必须在维护窗口停止业务读取并保留原始审计，不能把回退结果当作已满足本协议。
